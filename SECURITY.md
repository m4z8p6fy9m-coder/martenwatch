# Security policy

This is an educational local prototype. Do not expose it to the internet or use real invoices, credentials, customers or payments. The default application has no real authentication or production tenant isolation. See the [threat model](docs/SECURITY.md) and [architecture](docs/ARCHITECTURE.md).

## Reporting a vulnerability

If a future repository has GitHub private vulnerability reporting enabled, use its **Security → Report a vulnerability** option to report issues privately. Do not publish secrets or exploit details in a public issue. Until that channel has actually been configured, no private reporting contact or response-time guarantee is established. Maintainers must configure and verify such a channel before promoting this as a supported public project.

Only the current development version is intended to receive fixes; no supported releases or security patch SLA are currently defined.
